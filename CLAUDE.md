# Instant Replay — правила проекта

Общаемся по-русски, отвечай коротко и по делу. Перед правками изучай код (ничего не ломай), тесты
разрешены и желательны.

## Версия приложения (обязательно)

- При **каждом** изменении приложения обязательно обновляй его версию по SemVer `MAJOR.MINOR.PATCH`.
- Какую версию ставить дальше, решай сам:
  - `PATCH` (1.7.1 → 1.7.2) — исправление ошибки, мелкая правка, полировка интерфейса;
  - `MINOR` (1.7.2 → 1.8.0) — новая функция или заметное улучшение без поломки настроек;
  - `MAJOR` (1.8.0 → 2.0.0) — несовместимые изменения (формат настроек, крупная переработка).
  Исправления не смешивай с функциями без нужды: чинишь баг — патч, добавляешь функцию — минор.
- Версия хранится в одном месте: `Исходники/Cargo.toml` → `[package] version`. Интерфейс
  берёт её через `env!("CARGO_PKG_VERSION")`, поэтому больше нигде её не правь вручную.
- После смены версии добавь запись **сверху** в `Исходники/CHANGELOG.md` (по-русски).
- Версию повышай и при обновлении вшитого JustView.

## Структура

- `Исходники/` — весь исходный код (Rust, Cargo-проект). Кэш сборки лежит на `D:/cargo-target/instant-replay`
  (на E: нет места), задан в `Исходники/.cargo/config.toml`; не переноси `target` на E:.
- `Instant Replay/` — только готовый релизный билд: `Instant Replay.exe` (один файл, всё внутри).
- `Исходники/justview/` — копия проекта JustView (см. ниже), `Исходники/embed/` — упакованные JustView и
  FFmpeg для вшивания (в git не попадает).
- Сборка: `Исходники/build-release.ps1` (prepare-embed, тесты, release-сборка, копирование exe) или вручную
  `cargo test` + `cargo build --release`, потом копирование
  `D:/cargo-target/instant-replay/release/instant-replay.exe` в `Instant Replay/Instant Replay.exe`.

## Дизайн

- Все значения интерфейса (цвета, шрифты, отступы, радиусы, размеры, анимации) берутся из
  `Исходники/DESIGN.md` и `Исходники/src/ui/theme.rs`. Держи их синхронными.

## Рабочий порядок для каждой доработки

1. Изучи затронутый код, не ломай соседнее.
2. Правь код, повысь версию, допиши `CHANGELOG.md`.
3. `cargo test` (все тесты должны проходить), для нового поведения добавляй тесты.
4. Проверь на живом приложении (см. «Проверка»), а не только тестами. **Тестируй только то, что меняли, и то,
   что это могло затронуть**; не относящееся к изменениям заново не проверяй.
5. Собери release, закрой приложение, скопируй exe в `Instant Replay/`, **запусти приложение для пользователя**.
6. Закоммить (БЕЗ строки `Co-Authored-By` и без упоминаний Claude: пользователь не хочет соавторов), поставь тег
   `vX.Y.Z`, запушь `main` и тег, выпусти релиз на GitHub (см. ниже).
7. В итоговом ответе коротко скажи, что сделано, что проверено, и что **не** проверено.

## Запущенное приложение при проверке и установке

- Если для тестов или копирования exe нужно, чтобы Instant Replay был закрыт, закрывай его сам, не проси пользователя.
  Он работает с правами администратора, поэтому `taskkill` из обычной консоли его не закроет: используй
  `"Instant Replay\Instant Replay.exe" --quit` (просит запущенную копию выйти). Запомни, был ли он запущен.
- Запуск exe сам просит права администратора (UAC) - при установке новой версии предупреди пользователя, что нужно нажать «Да».
- После установки новой версии запускай её для пользователя из `Instant Replay/` (рабочая папка = эта
  папка), с тем же режимом, что был у него: если было свёрнуто в трей, запускай с `--tray`, иначе обычным окном.
- Тестовые копии exe запускай из временной папки (`$TEMP`), после проверки завершай их и вспомогательные
  процессы (`instant-replay.exe`, `ffplay.exe`, `JustView.exe`, тестовые окна). Не закрывай чужие окна
  (например, все окна Проводника по маске пути: у пользователя могут быть открыты свои).
- Приложение держит одну копию (single instance) и глобальные горячие клавиши: тестовая копия не заработает,
  пока запущено приложение пользователя. Для `--selftest` single instance отключён.
- Файлы пользователя трогай аккуратно: настройки `%APPDATA%\InstantReplay\config.json` перед
  экспериментами копируй и возвращай обратно, тестовые клипы и папки, которые создал при проверке, удаляй.

## Релиз на GitHub

- Релиз обновляй **только после тестов**: сначала `cargo test` и проверка изменённого в работе
  (по возможности на собранном exe), и лишь потом коммит, тег `vX.Y.Z` и `gh release create`.
- Репозиторий: `Spamerovith/Instant-Replay`. В релизе два файла: `Instant-Replay-X.Y.Z-windows-x64.zip`
  (внутри `Instant Replay.exe`) и отдельный `InstantReplay.exe` (его скачивает встроенное обновление).
- Текст релиза: заголовок `## Instant Replay X.Y.Z`, строка со ссылкой на скачивание, потом одни и те же
  пункты изменений, просто переведённые на английский, русский и украинский (три блока с одинаковым
  содержанием, без «пересказов»). Просмотрщик JustView называй «JustView (просмотрщик клипов на RUST)».
- Файлы с описанием и zip делай во временной папке (`$TEMP`), не в репозитории.

## JustView и FFmpeg внутри exe

- `Instant Replay.exe` один: JustView (просмотрщик клипов) и FFmpeg вшиты в него и при первом запуске
  распаковываются в `%LOCALAPPDATA%\InstantReplay\tools` (`src/tools.rs`, список файлов делает `build.rs`
  из `Исходники/embed/*.gz`). Для пользователя ничего ставить не нужно.
- Исходники JustView лежат в `Исходники/justview/` (копия проекта `E:\Claude\Приложения для ПК\JustView\Исходники`).
  **Любое изменение JustView делай в обоих местах:** в отдельном проекте JustView (версия, CHANGELOG,
  его `build.ps1`, при необходимости его релиз на GitHub) и в копии `Исходники/justview/` — просто
  копируй изменения. Потом пересобери Instant Replay, чтобы в exe попал новый JustView.
- FFmpeg — LGPL shared сборка BtbN, кэш в `D:/cargo-target/ffmpeg-cache` (скачивается один раз
  скриптом `Исходники/prepare-embed.ps1`, он же собирает вшиваемый JustView в `D:/cargo-target/justview-embedded`).
  Без файлов в `embed/` (обычный `cargo test`) приложение ищет установленные JustView и FFmpeg.
- Превью клипов и просмотр используют этот FFmpeg (`src/thumbs.rs`, `src/player/ffmpeg.rs`).

## Анти-читы (важно для игр)

- Ничего не внедряй в игры: никаких хуков (`SetWindowsHookEx`), `OpenProcess` и чтения памяти чужих процессов,
  инъекций DLL. Захват только штатным Windows Graphics Capture, горячие клавиши через `RegisterHotKey`.
- Имена процессов бери из снимка системы (`CreateToolhelp32Snapshot`, `src/capture/sources.rs`), а не
  открывая дескрипторы чужих процессов. Окна/игру на переднем плане определяй так же.

- Тест `anticheat_tests` (src/main.rs) не даёт добавить вызовы, которые ловят античиты; не обходи его.
- Программа работает с правами администратора (`src/elevation.rs`, настройка `run_as_admin`, перезапуск через runas до
  single instance). Они нужны для точного FPS: `src/frames/` - трекер кадров и ETW-сессия, взятые из AfterCore
  (`E:\Claude\Приложения для ПК\AfterCore`, сам AfterCore не менять). Автозапуск при правах - задача Планировщика.

## Устройство, которое легко сломать

- Оверлей (Alt+Z у пользователя, по умолчанию Ctrl+Alt+Z) — это то же окно eframe, переделанное через Win32
  (`src/ui/app.rs`: `place_as_overlay`, `restore_after_overlay`). Правила: окно прозрачно, пока не нарисованы
  первые кадры с нужным размером (`set_opaque`), системная анимация окна выключена (`set_transitions`),
  фокус берётся в отдельном потоке после отпускания Alt/Ctrl/Shift (иначе задержка), после закрытия окно
  уходит на дно z-порядка и фокус возвращается игре, главное окно не показывается.
- Настройки: движок хранит `base` (то, что видит и сохраняет пользователь) и `config` (действующие, с учётом
  профиля игры). Сохраняется и сравнивается только `base`.
- Профили игр (`config.rs`: `GameProfile`, `find_profile`; движок: `check_profile`) включаются, пока у игры есть
  окно; во время записи не переключаются.
- Клипы лежат в папках по играм (`engine.rs`: `clip_location`, `scan_clips`); игра в имени файла
  `<игра> - Replay|Recording <дата>.mp4`, по нему работает фильтр галереи (`clip_game`).
- Автобитрейт: `config.rs: auto_bitrate_mbps` (кодек, размер, fps, качество).
- Удаление клипа — только в Корзину (`src/recycle.rs`), всегда с подтверждением.

## Проверка

- Юнит-тесты: `cargo test` (в `Исходники/`).
- Режим `--selftest <папка> [h264|hevc|av1] [--rc vbr|cbr|cqp] [--bitrate N] [--res 720] [--profile exe.exe] [--window exe]`
  записывает реальные клипы и пишет `STATUS`/`TOOLS` в `%APPDATA%\InstantReplay\log.txt`.
- Размер/качество видео меряй стендом `--encode-test <клип.mp4> <папка> [кадров] [av1|hevc|h264] [Мбит/с]`: один и тот же
  клип кодируется нашим кодером с вариантами из `src/enctest.rs`, в log.txt строки `ENCTEST` с размером и SSIM к исходнику.
- Оверлей и интерфейс проверяй на живом приложении: горячие клавиши шли через `keybd_event`, окно снимай
  `CopyFromScreen`; чтобы оверлей попал на снимок, задай `INSTANT_REPLAY_ALLOW_CAPTURE=1` при запуске.
  Мерцание и задержку измеряй покадровой записью экрана (`ffmpeg -f gdigrab -framerate 60`) и опросом пикселей.
  «Игру» для проверок изображай тестовым полноэкранным окном (например, `ffplay -fs -f lavfi mandelbrot=...`).
- Горячие клавиши пользователя: оверлей Alt+Z, сохранить повтор Ctrl+Alt+F10, запись Ctrl+Alt+F9,
  быстрое сохранение Ctrl+Alt+F7, вкл/выкл Instant Replay Ctrl+Alt+F8 (Alt+F9/F10 занимает NVIDIA App).
  Клипы лежат в `D:\Instant Replay`.

## Подводные камни при работе

- Код с обратными слэшами (`\\?\`, пути) не записывай через `cat <<EOF` в Bash: слэши съедаются. Для такого
  кода используй Write/Edit, а в Rust — сырые строки `r"..."`.
- Скрипты PowerShell с кириллицей и `Add-Type` в Bash пиши в файл (Write), а не в одну строку.
- Сборка JustView медленная (до 4 минут): запускай в фоне. Релизная сборка Instant Replay около минуты.
- Перед `cargo build --release` убедись, что `CARGO_TARGET_DIR` не пустая переменная (`unset CARGO_TARGET_DIR`).
